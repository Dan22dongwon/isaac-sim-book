## 이 장에서 실측한 것

### ① 솔버 반복 횟수가 결과를 바꾼다 (ERR-037)

상자 6개(각 5 kg, 20 cm)를 쌓고 **반복 횟수만** 바꿔 200스텝.
효과를 가리지 않도록 `EnableStabilization` 은 껐다.

| 설정 | 최대 침하 | 꼭대기 높이 | 이상값 |
|---|---:|---:|---:|
| 반복 **1회** | **999.98 mm** | **0.100 m** | 1.100 m |
| 반복 4회 | 4.79 mm | 1.095 m | 1.100 m |
| 반복 **32회** | **0.21 mm** | **1.100 m** | 1.100 m |

반복 1회의 침하 1,000 mm 는 탑 전체 높이 1,200 mm 와 맞먹는다 —
**탑이 통째로 무너져 바닥에 깔렸다.** 32회에서는 0.21 mm, 머리카락 세 겹 두께다.

그림 `ch07_solver_iter01/04/32.png` 로도 한눈에 보인다.

### ② 타임스텝을 자유낙하로 검산한다 (ERR-039)

설정값을 읽어 보는 것만으로는 "먹혔다"를 알 수 없다.
공을 떨어뜨려 `d = ½·g·t²` 에서 `dt = √(2d/g) / 스텝수` 로 역산했다 (120스텝).

| 설정 physics_dt | 보고값 | 실측값 | 낙하거리 |
|---|---:|---:|---:|
| 1/60 | 0.016667 | 0.016736 | 19.783 m |
| 1/120 | 0.008333 | 0.008368 | 4.946 m |
| 1/240 | 0.004167 | 0.004184 | 1.236 m |
| 1/480 | 0.002083 | 0.002092 | 0.309 m |

낙하거리가 **정확히 ¼씩** 줄어든다. `d = ½g(N·dt)²` 이므로 dt 가 절반이면 거리는 ¼.

> 공이 느려진 게 아니라 **흘러간 시간이 달라진 것**이다.
> 120스텝 × 1/60초 = 2.00초, 120스텝 × 1/480초 = 0.25초.
> 같은 스텝 수라도 시뮬레이션 속 시간은 8배 차이다. 이것이 7장의 핵심 교환관계다.

### ③ 외력 API 를 뉴턴 역학으로 검산한다 (ERR-043)

5 kg 상자에 40 N, 타임스텝 1/120 s, **중력과 마찰을 0 으로** 두고 120스텝.

| | 실측 v | 이론 v | 실측 거리 | 이론 거리 |
|---|---:|---:|---:|---:|
| 순간 충격 | **0.0667 m/s** | 0.0667 m/s | 0.0667 m | 0.0667 m |
| 지속 압력 | **8.0000 m/s** | 8.0000 m/s | 4.0333 m | 4.0000 m |

```
순간 충격  Δv = F·Δt/m = 40 × (1/120) / 5 = 0.0667 m/s   ✅ 소수점까지 일치
지속 압력  Δv = F·t/m  = 40 × 1.000  / 5 = 8.0000 m/s   ✅ 소수점까지 일치
```

**'순간'과 '지속'은 전용 API 가 아니라 호출 시점으로 만든다.**
PhysX 의 외력은 원래 한 스텝만 유효하고 자동으로 사라진다.
한 스텝에만 부르면 충격, 매 스텝 부르면 지속이다.

## ⚠️ 주의-001 — `World` 는 싱글턴이다 (책에 언급 없음)

7장은 설정을 바꿔 가며 비교하는 장이라 **누구나 여기 걸린다.**

```python
w1 = World(physics_dt=1/60)
w2 = World(physics_dt=1/240)   # 새 객체가 아니다

w1 is w2               # True
w2.get_physics_dt()    # 0.016667  ← 1/240 을 줬는데 1/60 그대로
```

두 번째 호출은 기존 객체를 돌려주고 **생성자 인자를 조용히 무시한다.**
예외도 경고도 없다. 실제로 이 저장소를 만들며 걸렸다 — 네 가지 타임스텝을
비교했는데 **네 줄이 전부 같은 값**으로 나왔다.

```python
World.clear_instance()                       # 설정을 통째로 바꿀 때
world.set_simulation_dt(physics_dt=1/240)    # 타임스텝만 바꿀 때
```

`world.clear()` 는 씬만 비우고 인스턴스는 살려 두므로 이 용도로는 부족하다.

## ⚠️ 주의-002 — 씬 속성은 `world.reset()` 을 거쳐야 반영된다

솔버 설정을 바꿔 가며 비교하다가 걸린 함정이다.

```python
set_iterations(32)        # 속성만 바꾼다
# ... 시뮬레이션 계속 ...   → 꼭대기 0.100m  ❌ 반영 안 됨

set_iterations(32)
world.reset()             # 이걸 거쳐야 한다
for v in views: v.initialize()   # 리셋 후 뷰를 다시 잡는다
# ...                      → 꼭대기 1.100m  ✅ 반영됨
```

PhysX 는 씬 설정을 **씬을 올릴 때 읽는다.** 시뮬레이션 도중 USD 속성을 고쳐도
이미 돌고 있는 씬에는 적용되지 않는다. 예외도 경고도 없어서, GUI 데모에서
"반복 32회인데 탑이 무너진다"는 이상한 화면을 한참 보고 나서야 알았다.

`world.reset()` 뒤에는 `RigidPrim`·`Articulation` 뷰를 **다시 `initialize()`** 해야 한다.
리셋으로 물리 핸들이 새로 만들어지기 때문이다.

## 물체 단위 솔버 설정은 이 경우 효과가 없다

`PhysxRigidBodyAPI.CreateSolverPositionIterationCountAttr()` 로 물체마다 다른 값을
줄 수 있어서, 탑 셋을 한 화면에 나란히 세워 비교하려 했다. **실측해 보니 차이가
나지 않았다** (dt=1/60 에서 물체 반복 1·4·32 모두 꼭대기 1.100 m 로 정상).

그래서 데모는 같은 탑을 두고 **씬 설정을 바꿔 가며 번갈아** 보여 주는 방식으로 했다.
