# 5.10 Fusion 360에서 내 로봇 URDF 내보내기

> **이 절의 목표**: CAD로 직접 설계한 로봇을 URDF로 뽑아 Isaac Sim에 올리는 것.
> 앞 절들은 "URDF가 이미 있다"는 전제로 시작했다. 자작 로봇을 쓰려면 그 URDF를 먼저 만들어야 한다.

⚠️ **검증 범위**: 이 절의 Fusion 360 작업은 Fusion 360과 해당 플러그인이 필요해 이 책의 검증 환경(Ubuntu 24.04 + Isaac Sim 6.1)에서 실행 확인하지 못했다. 내보낸 URDF를 Isaac Sim에서 임포트하는 5.2절 이후 과정은 검증되어 있다. 플러그인 동작은 반드시 아래 GitHub 저장소의 최신 안내를 함께 확인하자.

---

## 5.10.1 왜 CAD에서 바로 뽑아야 하나

URDF를 손으로 쓰는 것은 가능하지만 현실적이지 않다. 링크마다 관성 텐서·질량·충돌 형상·조인트 축을 직접 계산해 넣어야 하는데, 다리가 넷인 로봇이면 링크만 13개다.

CAD 모델에는 이 정보가 이미 다 들어 있다. 부품의 부피와 재질에서 질량과 관성이 나오고, 조립 구속(joint)에서 회전축이 나온다. 플러그인은 그걸 읽어 URDF로 옮겨 적을 뿐이다.

| 방식 | 품질 | 수고 |
|---|---|---|
| 손으로 URDF 작성 | 관성값이 대충 들어가기 쉽다 | 매우 큼 |
| **CAD에서 내보내기** | 질량·관성이 설계값 그대로 | 모델 단순화 작업만 |
| 메시만 가져오고 물리는 수동 | 시각은 정확, 물리는 부정확 | 중간 |

## 5.10.2 플러그인 설치

Fusion 360에는 URDF 내보내기가 기본 탑재되어 있지 않다. 커뮤니티 플러그인을 설치해야 한다.

1. GitHub에서 **`fusion2urdf`** 를 검색해 저장소를 연다.
2. 녹색 **Code** 버튼 → **Download ZIP** 으로 내려받는다.
3. 압축을 푼다.
4. 저장소 README에 있는 설치 명령을 복사해 실행한다.

⚠️ **Windows에서는 반드시 PowerShell을 쓴다.** 구형 명령 프롬프트(`cmd`)에서는 설치 스크립트가 동작하지 않는다.

```powershell
cd Downloads
cd fusion2urdf-master
cd fusion2urdf-master
# README에 적힌 설치 한 줄을 여기에 붙여 넣는다
```

압축을 풀면 같은 이름의 폴더가 두 겹으로 생기는 경우가 많다. 스크립트 파일이 실제로 있는 안쪽 폴더까지 들어가야 한다.

설치에 성공하면 `successfully installed` 메시지가 나온다. 이미 설치되어 있으면 "already exists" 오류가 나는데, 이는 정상이다.

## 5.10.3 모델 단순화 — 이 절에서 가장 중요한 부분

플러그인을 돌리기 전에 **설계 모델을 시뮬레이션용으로 다듬어야 한다.** 이 작업을 건너뛰면 거의 반드시 실패한다.

### 지켜야 할 세 가지 규칙

**1. 중첩 컴포넌트가 없어야 한다**

컴포넌트 안에 컴포넌트가 들어 있으면 플러그인이 동작하지 않는다. 설계할 때는 `3D프린트 부품`, `서보모터` 같은 컴포넌트로 묶어 두는 것이 편하지만, 내보내기용 파일에서는 이 계층을 모두 풀어야 한다.

**2. 불필요한 고정 결합은 하나로 합친다**

나사로 붙어 있고 서로 움직이지 않는 부품들은 시뮬레이션에서 **하나의 바디**여야 한다. `Combine` 도구로 합친다. 서보모터도 그것이 붙은 암과 함께 합쳐 버리면 링크 수가 크게 줄어든다.

> 📌 4족 로봇 예: 다리마다 `고관절부 + 허벅지 + 정강이` 3개 바디, 다리 4개 = 12개, 여기에 몸통 1개 → **총 13개 바디**. 나사·케이블·커넥터는 전부 합쳐서 없앤다.

**3. 몸통 컴포넌트 이름은 반드시 `base_link`**

플러그인은 `base_link`라는 이름의 컴포넌트를 로봇의 루트로 삼는다. 이름이 다르면 동작하지 않는다. 밑줄까지 정확히 `base_link`여야 한다.

### 원본은 따로 보관한다

> ⚠️ **내보내기 전용 파일을 따로 만들자.** `Save As`로 `<로봇이름>_urdf_export` 같은 별도 파일을 만들어 거기서 단순화 작업을 한다.
>
> 이유는 두 가지다. 첫째, 설계를 수정할 일이 생기면 상세한 원본으로 돌아갈 수 있다. 둘째, **URDF 내보내기 플러그인은 실행 과정에서 모델 파일을 변경한다.** 원본에서 바로 돌렸다가 실패하면 복구가 번거롭다.

단순화가 끝나면 조인트는 "실제로 움직이는 것"만 남는다. 4족 로봇이라면 다리당 revolute 3개, 총 12개다.

## 5.10.4 내보내기 실행

1. Fusion 360 상단 **Utilities → Add-Ins → Scripts and Add-Ins** 를 연다.
2. 목록 아래쪽에서 **URDF Exporter** 를 찾는다. 없으면 설치가 실패한 것이다.
3. **Run(▶)** 을 누른다.
4. 저장할 폴더를 고른다.
5. 몇 초 뒤 `successfully create URDF file` 메시지가 나온다.

실행이 끝나면 모델에 임시 컴포넌트가 추가되어 있을 수 있다. **저장하지 말고 닫는다.**

### 생성된 파일

```
<선택한 폴더>/
└── <로봇이름>_description/
    ├── urdf/
    │   └── <로봇이름>.xacro      ← 이것이 우리가 쓸 파일
    ├── meshes/
    │   └── *.stl                ← 링크별 메시
    └── launch/, config/         ← ROS 2에서 쓸 때 필요
```

ROS 2와 함께 쓸 거라면 폴더 전체가 필요하다. Isaac Sim에만 올릴 거라면 `urdf/`와 `meshes/`만 있으면 된다.

### `.xacro` → `.urdf` 확장자 변경

> ⚠️ **플러그인은 `.urdf`가 아니라 `.xacro`를 만든다.** Isaac Sim의 URDF Importer는 `.urdf` 확장자를 기대한다.
>
> 두 형식은 구조가 거의 같으므로, **확장자만 `.xacro` → `.urdf`로 바꾸면** 대부분 그대로 임포트된다.

```bash
mv spiderbot.xacro spiderbot.urdf
```

📌 xacro는 URDF에 매크로·변수 기능을 더한 형식이다. 플러그인이 매크로를 쓰지 않고 평범한 URDF 내용만 적어 두기 때문에 확장자 변경만으로 통하는 것이다. 만약 파일 안에 `<xacro:...>` 태그가 있다면 `xacro` 명령으로 먼저 펼쳐야 한다.

```bash
# 파일 안에 xacro 태그가 있을 때만 필요하다
ros2 run xacro xacro spiderbot.xacro -o spiderbot.urdf
```

## 5.10.5 임포트 전 점검

온라인 URDF 뷰어로 미리 확인하면 좋겠지만, 실제로는 잘 동작하지 않는 경우가 많다. 다음 항목만 텍스트 편집기로 직접 확인하자.

- [ ] `<robot name="...">` 의 루트 링크가 `base_link` 인가?
- [ ] `<link>` 개수가 단순화한 바디 수와 같은가?
- [ ] `<joint type="revolute">` 개수가 실제 구동 관절 수와 같은가?
- [ ] 각 `<joint>` 의 `<axis xyz="...">` 가 의도한 회전축인가?
- [ ] `<mesh filename="...">` 경로가 `meshes/` 안의 실제 파일을 가리키는가?
- [ ] `<inertial>` 의 `<mass>` 가 0이 아닌가?

질량이 0인 링크가 있으면 Isaac Sim에서 물리가 발산한다. CAD에서 재질이 지정되지 않은 부품이 원인인 경우가 많다.

---

## 5.10.6 임포트가 실패할 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 플러그인이 목록에 안 보인다 | 설치 경로 오류 | 안쪽 폴더에서 설치 명령 재실행 |
| `base_link` 를 못 찾는다 | 컴포넌트 이름 불일치 | 이름을 정확히 `base_link` 로 |
| 내보내기가 중간에 멈춘다 | 중첩 컴포넌트 존재 | 계층을 모두 풀고 `Combine` |
| 링크가 너무 많다 | 고정 결합을 안 합침 | 움직이지 않는 부품끼리 합치기 |
| Isaac Sim에서 로봇이 터진다 | 질량 0 또는 관성 비정상 | CAD에서 재질 지정 후 재내보내기 |
| 조인트가 엉뚱하게 돈다 | 축 설정 오류 | 5.9절 Physics Inspector로 확인 |

> 💡 **모델이 복잡하면 거의 확실히 실패한다.** 바디가 수십 개이거나 조인트 종류가 섞여 있으면 플러그인이 처리하지 못한다. "일단 최대한 단순하게 만들어 성공시킨 뒤 조금씩 늘린다"가 가장 빠른 길이다.
